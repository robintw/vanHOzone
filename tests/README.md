# vanHOzone Tests

Comprehensive test suite for the vanHOzone package using modern pytest features.

## Overview

This test suite provides comprehensive coverage for the van Heuklon (1979) Ozone model implementation, testing the `get_ozone_conc` function across a wide range of scenarios using modern pytest features.

## Modern Pytest Features Used

### Parametrization
The tests extensively use `@pytest.mark.parametrize` to run the same test with different inputs, reducing code duplication and making tests more maintainable:

```python
@pytest.mark.parametrize("lat,lon,date,expected", [
    (40.7, -74.0, "2015-01-15", 330.35930121),  # Winter
    (40.7, -74.0, "2015-04-15", 360.65695415),  # Spring
    # ...
])
def test_season(self, lat, lon, date, expected):
    result = get_ozone_conc(lat, lon, date)
    assert result == pytest.approx([expected], rel=1e-7)
```

### Fixtures
Reusable test data is provided through fixtures in `conftest.py`:

```python
@pytest.fixture
def sample_locations():
    """Fixture providing sample geographic locations."""
    return {
        'london': (51.5, -0.1),
        'sydney': (-33.9, 151.2),
        # ...
    }
```

### pytest.approx for Floating Point Comparisons
Instead of manual epsilon checking, we use `pytest.approx` for robust floating-point comparisons:

```python
assert result == pytest.approx([383.85882587], rel=1e-7)
```

### Custom Markers
Tests are organized using custom markers:
- `@pytest.mark.vanhozone` - All tests for the package
- `@pytest.mark.slow` - Long-running tests
- `@pytest.mark.integration` - Integration tests

### Test Class Organization
Tests are organized into logical classes for better structure:
- `TestScalarInputs` - Tests for scalar inputs
- `TestArrayInputs` - Tests for array inputs
- `TestNorthernHemisphereSeasons` - Seasonal tests for NH
- `TestSouthernHemisphereSeasons` - Seasonal tests for SH
- And more...

## Running the Tests

### Basic Test Run

```bash
pytest
```

This will run all tests with the default configuration from `pytest.ini`.

### Verbose Output

```bash
pytest -v
```

### Run Specific Test Classes

```bash
pytest tests/test_vanHOzone.py::TestScalarInputs
```

### Run Specific Test

```bash
pytest tests/test_vanHOzone.py::TestScalarInputs::test_scalar_northern_hemisphere -v
```

### Run Tests by Marker

```bash
# Run only vanhozone tests
pytest -m vanhozone

# Run everything except slow tests
pytest -m "not slow"
```

### Coverage Report

```bash
pytest --cov=vanHOzone --cov-report=html
```

This generates an HTML coverage report in `htmlcov/index.html`.

### Show Test Output

```bash
pytest -v -s
```

The `-s` flag shows print statements and other output.

### Run Tests in Parallel (requires pytest-xdist)

```bash
pip install pytest-xdist
pytest -n auto
```

### Stop on First Failure

```bash
pytest -x
```

### Show Local Variables on Failure

```bash
pytest -l
```

### Detailed Summary

```bash
pytest -ra
```

Shows summary of all test outcomes (passed, failed, skipped, etc.)

## Writing New Tests

When adding new tests:

1. Use descriptive test names starting with `test_`
2. Add docstrings explaining what the test does
3. Use `pytest.approx` for floating-point comparisons
4. Use `@pytest.mark.parametrize` for similar tests with different data
5. Organize tests into logical classes
6. Add appropriate markers if needed
7. Use fixtures for reusable test data

Example:

```python
@pytest.mark.parametrize("lat,lon,expected", [
    (51.5, -0.1, 383.858),
    (-33.9, 151.2, 313.502),
])
def test_my_new_test(lat, lon, expected):
    """Test description here."""
    result = get_ozone_conc(lat, lon, "2015-06-15")
    assert result == pytest.approx([expected], rel=1e-3)
```
